# UI/UX STANDARDS — استاندارد طراحی یکپارچه

**مالک:** Agent G (Design System & Accessibility) — تأیید: Agent A
**مبنای اولیه:** آنچه امروز در کد موجود است باید ابتدا **کشف** شود، سپس یکپارچه شود. این سند قواعد الزامی است، نه پیشنهاد.

---

## 1. Design Tokens (منبع واحد حقیقت)

پیش از هر تغییر، توکن‌های موجود از `frontend/src/theme/**` استخراج و اینجا ثبت می‌شوند. تا زمان استخراج، موارد زیر الزامی است:

| گروه | قاعده |
|---|---|
| رنگ | فقط از توکن‌های theme استفاده شود. رنگ hardcode در صفحات ممنوع. |
| رنگ‌های وضعیت | `success` / `warning` / `error` / `info` معنا و کاربرد ثابت دارند؛ تغییر معنایی در صفحات مختلف ممنوع. |
| Spacing | مقیاس ثابت (۴ یا ۸ پیکسلی). فاصله‌های دلخواه یک‌بارمصرف ثبت و حذف می‌شوند. |
| Radius | تعداد محدود (مثلاً ۸ / ۱۲ / ۱۶) — نه مقدار دلبخواه در هر کارت. |
| Elevation | حداکثر ۲ سطح سایه برای محتوای معمولی. سایهٔ سنگین/گرادیان تزئینی غیرضروری حذف. |
| Typography | سلسله‌مراتب ثابت تیترها (h1..h4)، اندازهٔ متن پایهٔ قابل‌خواندن در موبایل. |

## 2. لمس (Touch)

- هدف لمس دکمه‌ها/آیکون‌های عملیاتی: **≥ ۴۴×۴۴ CSS px** (ترجیح 48).
- دکمه‌های آیکونی بدون برچسب باید `aria-label` داشته باشند.
- فاصلهٔ عملیات خطرناک (حذف/لغو) از عملیات عادی.
- حالت‌های `disabled` و `loading` بصری و واضح.
- جلوگیری از ثبت تکراری: دکمه در زمان درخواست `disabled`.

## 3. فرم‌ها

- Label همیشه دیده‌شود (نه فقط placeholder).
- اعتبارسنجی با پیام خطای مشخص و فارسی، نزدیک فیلد.
- حفظ داده پس از خطای قابل‌بازیابی.
- `type`/`inputMode` مناسب موبایل (tel / email / number).
- نمایش خطای Backend در فرم (نه فقط toast گنگ).
- فرم‌های طولانی بخش‌بندی منطقی.

## 4. وضعیت‌های صفحه (الزامی برای همهٔ صفحات داده‌محور)

`Loading` (Skeleton ترجیحاً) · `Empty` (پیام + اقدام بعدی) · `Error` (+ Retry) · `Success` · `Disabled` · `Partial`.

ممنوع: پیام موفقیت پیش از تأیید Backend.

## 5. RTL و فارسی

- `dir="rtl"` در ریشه/محل صحیح.
- جهت فلش‌های ناوبری و آیکون‌های «بعدی/قبلی» درست.
- اعداد، مبلغ، تاریخ شمسی و شماره تلفن با فرمت و جهت صحیح.
- عدم شکستن layout با متن طولانی فارسی/انگلیسی ترکیبی.

## 6. موبایل

- بدون اسکرول افقی ناخواسته در هیچ viewport (از 320px).
- دکمهٔ اقدام اصلی در دیدرس (بدون اسکرول زیاد یا با sticky action).
- جدول‌های عریض → کارت یا اسکرول کنترل‌شده.
- Modal/Dialog داخل صفحه بماند (max-width/height + اسکرول داخلی).
- Bottom navigation فقط آیتم‌های ضروری + تب فعال مشخص.

## 7. مینیمالیسم

- هر صفحه یک هدف اصلی.
- کارت‌های تکراری ادغام، آمار کم‌اهمیت به بخش فرعی، جزئیات به صفحهٔ جزئیات.
- تب فقط با دسته‌بندی معنادار.

## 8. قواعد ممنوعهٔ تغییر

- حذف قابلیت موجود به بهانهٔ شلوغی ممنوع.
- تغییر منطق تاریخ/مبلغ/دادهٔ Backend برای زیبایی ممنوع.
- افزودن رنگ/سایه/افکت جدید بدون ثبت در این سند ممنوع.
