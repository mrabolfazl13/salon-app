# تحلیل نقش مشتری/ورزشکار - سیستم رزرو فوتسال

## خلاصه اجرایی

این سند تحلیلی جامع از تجربه کاربری مشتریان در سیستم رزرو فوتسال ارائه می‌دهد. بر اساس بررسی کدهای فرانت‌اند (`src/pages/`)، نقاط قوت و ضعف فعلی شناسایی شده و راهکارهای عملی برای بهبود هر بخش پیشنهاد شده است.

---

## ۱. یافتن سالن‌ها (جستجو، فیلتر، موقعیت، قیمت، امکانات، تصاویر)

### وضعیت فعلی

**صفحات مرتبط:** `Home.tsx`, `Search.tsx`, `Venues.tsx`, `VenueDetail.tsx`

#### جستجو
- **پیاده‌سازی:** کامپوننت `SearchBar` با قابلیت debounce 350ms
- **مکانیزم:** جستجوی متنی سمت سرور از طریق `venueService.getAll({ search: q })`
- **تاریخچه:** ذخیره‌سازی خودکار در Zustand store (`searchHistoryStore`)
- **جستجوهای محبوب:** لیست ثابت شامل 'فوتبال', 'بدنسازی', 'چمن مصنوعی' و غیره

#### فیلترها
- **Bottom Sheet:** کامپوننت `FilterBottomSheet` با قابلیت‌های:
  - بازه قیمت (minPrice/maxPrice)
  - ورزش خاص (sportKey)
  - فقط تأییدشده (verifiedOnly)
  - امکانات (amenities array)
- **چیپ‌های فعال:** نمایش فیلترهای اعمال‌شده با امکان حذف تکی
- **دسته‌بندی:** سوئیچ بین فوتسال و بدنسازی

#### موقعیت مکانی
- **دریافت مختصات:** استفاده از `navigator.geolocation`
- **محاسبه فاصله:** ارسال lat/lng به API با شعاع پیش‌فرض 15 کیلومتر
- **UI:** دکمه "فعال‌سازی" برای درخواست صریح دسترسی
- **fallback:** در صورت عدم دسترسی، سالن‌های عمومی نمایش داده می‌شود

#### قیمت
- **نمایش:** استفاده از `formatPrice` با اعداد فارسی
- **مرتب‌سازی:** امکان مرتب‌سازی بر اساس ارزان‌ترین/گران‌ترین
- **فیلتر:** اسلایدر بازه قیمت با سقف پویا بر اساس داده‌های واقعی

#### امکانات
- **استخراج خودکار:** از فیلد `amenities` سالن‌ها
- **نمایش:** چیپ‌های قابل انتخاب در فیلتر
- **آیکون‌ها:** استفاده از Iconify با آیکون‌های mdi

#### تصاویر
- **گالری:** اسکرول افقی در موبایل (scroll-snap)
- **Fallback:** گرادیان برند در صورت عدم بارگذاری تصویر
- **بهینه‌سازی:** lazy loading + error handling

### مشکل

1. **جستجوی محدود:** فقط جستجوی نام و آدرس؛ بدون پشتیبانی از فیلتر ترکیبی (مثلاً "فوتسال نزدیک من زیر 500 هزار")
2. **عدم وجود نقشه تعاملی پیشرفته:** کامپوننت `VenueMap` ساده است و امکاناتی مانند مسیریابی یا لایه‌بندی قیمت ندارد
3. **فیلترهای پیچیده:** Bottom Sheet ممکن است برای کاربران تازه‌وارد گیج‌کننده باشد
4. **تصاویر کم‌کیفیت:** سیستم آپلود/فشرده‌سازی تصاویر مشخص نیست
5. **بدون پیش‌نمایش ویدیو:** امکان مشاهده ویدیو از سالن وجود ندارد

### راهکار پیشنهادی

#### کوتاه‌مدت (1-2 هفته)
1. **افزودن جستجوی هوشمند:**
   ```typescript
   // src/services/venue.ts - افزودن پارامترهای ترکیبی
   interface SearchParams {
     search?: string
     sport?: string
     maxPrice?: number
     near_lat?: number
     near_lng?: number
     radius_km?: number
     amenities?: string[]
   }
   ```

2. **بهبود UI فیلترها:**
   - اضافه کردن tooltip برای هر فیلتر
   - نمایش تعداد نتایج هنگام تغییر هر فیلتر
   - دکمه "ذخیره فیلتر" برای جستجوهای مکرر

3. **بهینه‌سازی تصاویر:**
   - افزودن WebP support
   - نمایش thumbnail قبل از لود کامل
   - Lightbox برای گالری تصاویر

#### میان‌مدت (1-2 ماه)
1. **جستجوی معنایی:**
   - استفاده از Elasticsearch یا Algolia
   - پشتیبانی از typo-tolerance ("فوتسبال" → "فوتبال")
   - Auto-complete با پیشنهادات هوشمند

2. **نقشه پیشرفته:**
   - لایه‌بندی قیمت با heat map
   - مسیریابی داخلی به سالن
   - نمایش ترافیک لحظه‌ای اطراف سالن

3. **ویدیو و تور مجازی:**
   - امکان آپلود ویدیو 360 درجه توسط مدیران
   - پخش خودکار preview در hover (دسکتاپ)

### نتیجه مورد انتظار

- **کاهش 40% زمان جستجو** با جستجوی هوشمند
- **افزایش 25% نرخ تبدیل** با نمایش بهتر امکانات
- **بهبود رضایت کاربر** با نقشه تعاملی و مسیریابی

## ۲. مشاهده موجودی و سانس‌ها

### وضعیت فعلی

**صفحات مرتبط:** `VenueDetail.tsx`, `components/booking/TimeSlotPicker.tsx`

#### انتخاب تاریخ
- **DateSelector:** نمایش 14 روز آینده با اسکرول افقی
- **فرمت jalali:** استفاده از `buildDateOptions` با تاریخ شمسی
- **برجسته‌سازی:** امروز با رنگ متفاوت

#### نمایش سانس‌ها
- **TimeSlot Component:** نمایش ساعت شروع/پایان، قیمت، وضعیت
- **وضعیت‌ها:** available, booked, in_competition
- **رقابت قیمت:** سانس‌های `in_competition` دارای دکمه "پیشنهاد قیمت"

#### اطلاعات سانس
- **مدت زمان:** محاسبه پویا پایان بر اساس duration
- **قیمت داینامیک:** نمایش `current_price` (با احتساب تخفیف رقابت)
- **صف انتظار:** دکمه "ورود به صف انتظار" برای سانس‌های پر

### مشکل

1. **بارگذاری کند:** دریافت تمام سانس‌های 14 روز در یک درخواست
2. **عدم شفافیت:** کاربر نمی‌داند چرا برخی سانس‌ها گران‌ترند (تعطیلات؟ ساعات اوج؟)
3. **صف انتظار غیرفعال:** کاربر از جایگاه خود در صف مطلع نمی‌شود
4. **بدون یادآوری:** هیچ سیستمی برای اطلاع‌رسانی آزاد شدن سانس وجود ندارد

### راهکار پیشنهادی

#### کوتاه‌مدت
1. **Lazy Loading سانس‌ها:**
   ```typescript
   // فقط سانس‌های هفته جاری را لود کن
   const [weekOffset, setWeekOffset] = useState(0)
   useEffect(() => {
     fetchSlots(selectedDate, weekOffset)
   }, [selectedDate, weekOffset])
   ```

2. **Tooltip توضیح قیمت:**
   - نمایش عوامل افزایش/کاهش قیمت در hover
   - مثال: "تعطیلات رسمی (+20%)", "ساعت اوج (+15%)"

3. **شفاف‌سازی صف انتظار:**
   - نمایش شماره جایگاه کاربر
   - تخمین زمان رسیدن نوبت

#### میان‌مدت
1. **سیستم Notification:**
   - WebSocket برای اطلاع‌رسانی لحظه‌ای آزاد شدن سانس
   - Push notification در اپ موبایل

2. **پیش‌بینی موجودی:**
   - ML model برای پیش‌بینی احتمال آزاد شدن سانس
   - نمایش درصد احتمال ("80% احتمال لغو")

### نتیجه مورد انتظار

- **کاهش 60% زمان لود صفحه** با lazy loading
- **افزایش 30% اعتماد کاربر** با شفاف‌سازی قیمت‌گذاری
- **بهبود 20% نرخ پر شدن سانس‌ها** با سیستم اطلاع‌رسانی هوشمند

## ۳. فرآیند رزرو (پرداخت، لغو، تغییرات)

### وضعیت فعلی

**صفحات مرتبط:** `VenueDetail.tsx`, `Bookings.tsx`, `BookingDetail.tsx`

#### فرآیند رزرو
1. **انتخاب سانس:** کلیک روی TimeSlot
2. **دیالوگ تأیید:** Dialog با خلاصه رزرو
3. **کد تخفیف:** TextField اختیاری
4. **امتیاز وفاداری:** Checkbox "استفاده از امتیازها (تا 50%)"
5. **ثبت:** فراخوانی `bookingService.create()`
6. **وضعیت:** pending تا تایید مدیر

#### پرداخت
- **روش‌ها:** 
  - درگاه آنلاین (gateway)
  - فیش واریزی (bank_receipt)
  - پرداخت در محل (pay_in_place)
- **PaymentDialog:** کامپوننت جداگانه برای پرداخت
- **ریز قیمت:** PricingBreakdown با جزئیات محاسبات سرور

#### لغو رزرو
- **ConfirmModal:** دیالوگ تأیید با هشدار
- **Redis pending:** لغو سریع رزروهای تایید نشده
- **بازگشت وجه:** خودکار برای رزروهای paid

#### تغییرات
- **عدم پشتیبانی:** در حال حاضر امکان تغییر تاریخ/سانس وجود ندارد
- **راهکار فعلی:** لغو + رزرو مجدد

### مشکل

1. **فرآیند چند مرحله‌ای:** کاربر باید 4-5 کلیک انجام دهد
2. **عدم شفافیت هزینه‌ها:** ریز قیمت فقط بعد از ثبت نمایش داده می‌شود
3. **لغو سخت‌گیرانه:** بدون امکان تغییر، فقط لغو کامل
4. **زمان تایید طولانی:** pending تا وقتی مدیر تایید کند
5. **بدون تقویم اشتراکی:** نمی‌توان رزرو را با دوستان به اشتراک گذاشت

### راهکار پیشنهادی

#### کوتاه‌مدت
1. **One-Click Booking:**
   ```typescript
   // ذخیره prefernces کاربر
   interface BookingPreferences {
     paymentMethod: 'gateway' | 'receipt' | 'in_place'
     useLoyalty: boolean
     defaultDiscountCode?: string
   }
   ```

2. **نمایش زنده قیمت:**
   - محاسبه قیمت قبل از ثبت در sidebar
   - نمایش تاثیر کد تخفیف به صورت real-time

3. **امکان تغییر رزرو:**
   - endpoint جدید: `PUT /bookings/:id/reschedule`
   - محدودیت: حداکثر 24 ساعت قبل از سانس

#### میان‌مدت
1. **تایید خودکار:**
   - برای کاربران trusted (بیش از 5 رزرو موفق)
   - الگوریتم fraud detection ساده

2. **اشتراک‌گذاری رزرو:**
   - تولید لینک shareable
   - QR code برای check-in سریع
   - دعوت دوستان به بازی از طریق SMS

3. **سیستم Split Payment:**
   - تقسیم هزینه بین چند نفر
   - ارسال لینک پرداخت به هر شرکت‌کننده

### نتیجه مورد انتظار

- **کاهش 50% زمان رزرو** با one-click booking
- **افزایش 35% رضایت** با امکان تغییر بجای لغو
- **بهبود 25% نرخ تکمیل پرداخت** با split payment

## ۴. دعوت دوستان، اشتراک‌گذاری رزرو

### وضعیت فعلی

**تحلیل:** این قابلیت **اصلاً پیاده‌سازی نشده** است.

- هیچ دکمه share در `BookingDetail.tsx` وجود ندارد
- سیستم invite دوست در `Profile.tsx` یا صفحات دیگر نیست
- تنها اشاره غیرمستقیم: کامپوننت `GameCreate.tsx` برای ایجاد بازی گروهی

### مشکل

1. **از دست دادن viral growth:** کاربران نمی‌توانند برنامه را به دوستان معرفی کنند
2. **سختی هماهنگی تیم:** کاپیتان تیم باید دستی با همه هماهنگ کند
3. **بدون referral system:** انگیزه‌ای برای دعوت دیگران وجود ندارد

### راهکار پیشنهادی

#### کوتاه‌مدت
1. **Share Button در BookingDetail:**
   ```typescript
   <Button
     startIcon={<Icon icon="mdi:share-variant" />}
     onClick={() => {
       const url = `${window.location.origin}/bookings/${booking.id}`
       navigator.share?.({ title: 'رزرو من', url })
     }}
   >
     اشتراک‌گذاری
   </Button>
   ```

2. **Deep Linking:**
   - `/bookings/:id?view=public` برای نمایش اطلاعات بدون لاگین
   - QR code generator برای check-in سریع

#### میان‌مدت
1. **Invite System:**
   - صفحه "دعوت دوستان" در Profile
   - ارسال SMS/email با لینک ثبت‌نام
   - امتیاز وفاداری برای هر دوست دعوت‌شده

2. **Team Coordination:**
   - ایجاد رویداد بازی در `GamesExplore.tsx`
   - ارسال invite به اعضای تیم
   - RSVP (بله/خیر/شاید)

3. **Referral Program:**
   - کد معرف منحصر به فرد
   - تخفیف برای معرف و معرفی‌شونده
   - داشبورد پیگیری referrals

### نتیجه مورد انتظار

- **افزایش 40% رشد ارگانیک** با referral program
- **کاهش 60% زمان هماهنگی تیم** با invite system
- **بهبود engagement** با gamification دعوت

## ۵. مشاهده تاریخچه، علاقه‌مندی‌ها، امتیازدهی

### وضعیت فعلی

#### تاریخچه رزروها
**صفحه:** `Bookings.tsx`
- **تب‌ها:** همه، تایید شده، در انتظار، لغو شده، انجام شده
- **نمایش:** کارت‌های VenueCard با اطلاعات خلاصه
- **فیلتر:** بر اساس status
- **عملیات:** پرداخت، لغو، مشاهده جزئیات

#### علاقه‌مندی‌ها
**صفحه:** `Favorites.tsx`
- **ذخیره‌سازی:** client-side با Zustand (`favoritesStore`)
- **نمایش:** گرید VenueCard مشابه Venues page
- **حذف:** دکمه "پاک کردن همه"
- **مشکل:** اگر سالن حذف شود، empty state نشان می‌دهد

#### امتیازدهی و نظرات
**کامپوننت:** `ReviewSection.tsx` (در `VenueDetail.tsx`)
- **Rating:** ستاره‌ای 1-5 با نیم‌ستاره
- **نظرات متنی:** کاربران می‌توانند نظر بنویسند
- **Aggregate:** نمایش average_rating و total_reviews
- **Update:** پس از ثبت نظر، مقادیر venue آپدیت می‌شوند

### مشکل

1. **تاریخچه بدون جستجو:** نمی‌توان در رزروهای قدیمی جستجو کرد
2. **علاقه‌مندی‌ها client-side:** با پاک کردن cache از بین می‌رود
3. **بدون دسته‌بندی علاقه‌مندی:** نمی‌توان لیست‌های مختلف ساخت (مثلاً "سالن‌های شمال شهر")
4. **امتیازدهی یک‌طرفه:** فقط کاربر امتیاز می‌دهد، پاسخی از طرف مدیر نیست
5. **بدون عکس در نظرات:** کاربران نمی‌توانند عکس از تجربه خود آپلود کنند

### راهکار پیشنهادی

#### کوتاه‌مدت
1. **Persist Favorites:**
   ```typescript
   // ذخیره در localStorage یا backend
   const persistFavorites = async (favorites: Favorite[]) => {
     await api.post('/user/favorites', favorites)
   }
   ```

2. **جستجو در تاریخچه:**
   - Search bar در Bookings page
   - فیلتر بر اساس تاریخ، سالن، مبلغ

3. **پاسخ مدیر به نظرات:**
   - endpoint جدید: `POST /reviews/:id/reply`
   - نمایش پاسخ در زیر نظر اصلی

#### میان‌مدت
1. **Smart Lists:**
   - امکان ساخت لیست‌های شخصی ("سالن‌های مورد علاقه"، "برای مسابقه")
   - اشتراک‌گذاری لیست با دوستان

2. **Rich Reviews:**
   - آپلود عکس همراه نظر
   - امتیازدهی تفکیکی (تمیزی، کیفیت چمن، برخورد پرسنل)
   - Verified badge برای رزروهای تکمیل‌شده

3. **Analytics تاریخچه:**
   - نمودار هزینه ماهانه
   - ورزش‌های پرطرفدار
   - پیشنهاد سالن بر اساس تاریخچه

### نتیجه مورد انتظار

- **افزایش 50% engagement** با smart lists
- **بهبود 30% کیفیت نظرات** با rich reviews
- **کاهش 20% churn** با persist favorites

## ۶. تخفیف‌ها، کیف پول، پرداخت اشتراکی

### وضعیت فعلی

#### تخفیف‌ها
**صفحه:** `Deals.tsx`
- **Last-minute deals:** سانس‌های خالی با تخفیف
- **فیلترها:** حداکثر قیمت، زمان روز (صبح/عصر/شب)، مرتب‌سازی
- **رقابت قیمت:** CompetitionBidDialog برای پیشنهاد قیمت پایین‌تر
- **Subscription:** اشتراک اعلان تخفیف‌ها در Profile

#### کیف پول/وفاداری
**صفحه:** `Profile.tsx` (تب وفاداری)
- **امتیاز:** balance با ارزش ریالی مشخص
- **تاریخچه:** loyalty history با دلایل کسب/مصرف
- **استفاده:** تا 50% مبلغ رزرو قابل پرداخت با امتیاز
- **دستاوردها:** badges gamification

#### پرداخت اشتراکی
**تحلیل:** **پیاده‌سازی نشده**

### مشکل

1. **Deals محدود:** فقط last-minute، بدون تخفیف‌های برنامه‌ریزی‌شده
2. **بدون کیف پول ریالی:** فقط امتیاز وفاداری، نه شارژ مستقیم
3. **عدم شفافیت قوانین تخفیف:** کاربر نمی‌داند چرا بعضی سانس‌ها تخفیف دارند
4. **بدون subscription plan:** اشتراک ماهانه/فصلی برای کاهش هزینه

### راهکار پیشنهادی

#### کوتاه‌مدت
1. **Wallet Top-up:**
   ```typescript
   // endpoint جدید
   POST /wallet/charge { amount: number }
   GET /wallet/balance
   ```

2. **Coupon Categories:**
   - تخفیف اولین رزرو
   - تخفیف تولد
   - تخفیف مناسبتی (نوروز، یلدا)

3. **Split Payment MVP:**
   - تولید لینک پرداخت برای هر نفر
   - tracking وضعیت پرداخت هر شرکت‌کننده

#### میان‌مدت
1. **Subscription Plans:**
   - پلن برنزی: 5% تخفیف همه رزروها
   - پلن نقره‌ای: 10% + اولویت در صف انتظار
   - پلن طلایی: 15% + تایید خودکار

2. **Dynamic Discounts:**
   - تخفیف بر اساس loyalty tier
   - تخفیف گروهی (3+ نفر)
   - Flash sales ساعتی

3. **Gift Cards:**
   - خرید کارت هدیه برای دوستان
   - اعتبار هدیه مناسبتی

### نتیجه مورد انتظار
