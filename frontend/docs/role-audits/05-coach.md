# حسابرسی نقش: مربی (Coach)

## خلاصه اجرایی

مربی در سیستم رزرو فوتسال نقشی حیاتی اما کمتر دیده‌شده دارد. او واسط بین ورزشکاران، زمین تمرین و مدیریت مالی تیم است. مربی مسئول برنامه‌ریزی جلسات تمرینی، پیگیری حضور و غیاب شاگردان، مدیریت پرداخت‌های شهریه، و ارزیابی پیشرفت بازیکنان است. چالش اصلی این نقش، نبود ابزارهای یکپارچه برای مدیریت همزمان جنبه‌های آموزشی، مالی و لجستیکی تمرینات است.

## دامنه دسترسی و مجوزها

### وضعیت فعلی: عدم وجود نقش اختصاصی مربی

بررسی کد موجود نشان می‌دهد که **هیچ نقش اختصاصی برای مربی** در سیستم تعریف نشده است. در فایل `src/types/team.ts`، تنها نقش‌های زیر برای اعضای تیم تعریف شده‌اند:

```typescript
export type TeamRole = 'captain' | 'admin' | 'member'
```

این یعنی مربیان یا باید به عنوان «عضو عادی» ثبت شوند (که دسترسی محدودی دارند) یا به عنوان «کاپیتان/مدیر» (که دسترسی بیش از حد دارند). هیچ میانگینی وجود ندارد.

### دسترسی‌های مورد نیاز مربی

بر اساس تحلیل نیازمندی‌های واقعی مربیان فوتسال، دسترسی‌های زیر ضروری است:

**۱. مدیریت برنامه تمرینی:**
- ایجاد و ویرایش برنامه هفتگی/ماهانه تمرینات
- رزرو زمین برای جلسات تمرینی (با اولویت نسبت به کاربران عادی)
- لغو یا جابه‌جایی جلسه با اعلان خودکار به شاگردان

**۲. مدیریت شاگردان:**
- مشاهده لیست شاگردان تحت آموزش
- ثبت نام شاگرد جدید در کلاس/تیم
- حذف شاگرد (با حفظ تاریخچه)
- مشاهده اطلاعات تماس و سوابق پرداخت

**۳. حضور و غیاب:**
- ثبت حضور/غیاب در هر جلسه تمرینی
- محاسبه درصد حضور ماهانه
- اعلان خودکار به والدین (برای شاگردان زیر ۱۸ سال)

**۴. مدیریت مالی:**
- مشاهده وضعیت پرداخت شهریه شاگردان
- ایجاد فاکتور شهریه ماهانه
- ثبت پرداخت نقدی/کارت‌به‌کارت
- ارسال یادآوری پرداخت به شاگردان بدهکار

**۵. گزارش پیشرفت:**
- ثبت ارزیابی مهارت‌ها (پاس، شوت، دریبل، دفاع)
- نمودار رشد شاگرد در طول زمان
- تولید گزارش PDF برای ارائه به والدین یا باشگاه

## شکاف‌های شناسایی شده

### شکاف ۱: عدم امکان رزرو زمین توسط مربی

**شرح مشکل:**
در حال حاضر، فقط کاربران عادی می‌توانند زمین رزرو کنند (`src/pages/games/GameCreate.tsx`). مربی نمی‌تواند مستقیماً برای تیم یا کلاس خود زمین رزرو کند مگر اینکه خودش را به عنوان «سازنده بازی» معرفی کند. این فرآیند غیرمستقیم و ناکارآمد است.

**مثال واقعی:**
مربی علی آقا می‌خواهد برای تیم نوجوانان خود، سه جلسه تمرینی در هفته (شنبه، دوشنبه، چهارشنبه ساعت ۱۷) رزرو کند. در سیستم فعلی، او باید:
1. ابتدا به عنوان کاربر عادی وارد شود
2. سه رزرو جداگانه ایجاد کند
3. سپس برای هر رزرو یک «بازی گروهی» بسازد
4. تک‌تک شاگردان را دعوت کند

این فرآیند ۱۵-۲۰ دقیقه زمان می‌برد، در حالی که باید با ۳ کلیک انجام شود.

**راه‌حل پیشنهادی:**
افزودن نقش `coach` به `TeamRole` و ایجاد صفحه اختصاصی `CoachSchedule.tsx`:

```typescript
// src/types/coach.ts
export interface TrainingSession {
  id: number
  coach_id: number
  team_id?: number
  venue_id: number
  slot_date: string      // YYYY-MM-DD
  start_time: string     // HH:MM
  duration: number       // دقیقه
  attendees: number[]    // user_id شاگردان حاضر
  notes?: string
}

export interface CoachSchedule {
  sessions: TrainingSession[]
  total_sessions: number
  upcoming_sessions: number
}
```

### شکاف ۲: فقدان سیستم حضور و غیاب

**شرح مشکل:**
مربیان در حال حاضر از کاغذ، اکسل یا اپلیکیشن‌های متفرقه برای ثبت حضور و غیاب استفاده می‌کنند. این داده‌ها در سیستم اصلی ذخیره نمی‌شوند و قابل گزارش‌گیری نیستند.

**پیامدها:**
- نمی‌توان درصد حضور شاگردان را محاسبه کرد
- نمی‌توان الگوی ترک تحصیل (Dropout) را شناسایی کرد
- والدین از غیبت فرزند خود مطلع نمی‌شوند

**راه‌حل پیشنهادی:**
ماژول حضور و غیاب در صفحه جزئیات تیم:

```typescript
// src/components/coach/AttendanceTracker.tsx
interface AttendanceRecord {
  session_id: number
  user_id: number
  status: 'present' | 'absent' | 'late' | 'excused'
  marked_at: string
  marked_by: number  // coach_id
}
```

ویژگی‌ها:
- رابط سریع تیک‌زدن (Checkbox Grid) برای ثبت حضور همه شاگردان در ۳۰ ثانیه
- محاسبه خودکار درصد حضور ماهانه
- اعلان خودکار به شاگردانی که ۳ جلسه متوالی غیبت کرده‌اند

### شکاف ۳: عدم یکپارچگی پرداخت شهریه با سیستم مالی تیم

**شرح مشکل:**
در فایل `src/types/team.ts`، مدل `TeamDue` برای مدیریت حصه‌های تیمی وجود دارد، اما این مدل برای شهریه مربیگری مناسب نیست زیرا:
- شهریه معمولاً ماهانه و ثابت است، نه بر اساس رویداد
- ممکن است تخفیف خانوادگی (مثلاً دو فرزند از یک خانواده) اعمال شود
- نیاز به فاکتور رسمی دارد

**راه‌حل پیشنهادی:**
ایجاد مدل اختصاصی `CoachFee`:

```typescript
// src/types/coach.ts
export interface CoachFee {
  id: number
  coach_id: number
  student_user_id: number
  amount: number
  period_start: string  // YYYY-MM-DD
  period_end: string
  is_paid: boolean
  paid_at?: string
  payment_method?: 'cash' | 'gateway' | 'card_to_card'
  discount_percent?: number
  discount_reason?: string
  invoice_number?: string
}

export interface CoachFeeSummary {
  total_fees: number
  paid_fees: number
  unpaid_fees: number
  overdue_fees: number
  students_count: number
}
```

### شکاف ۴: نبود ابزار ارزیابی پیشرفت شاگرد

**شرح مشکل:**
مربیان برای ارزیابی شاگردان از دفترچه یادداشت یا حافظه خود استفاده می‌کنند. هیچ ساختار استانداردی برای ثبت مهارت‌ها و پیشرفت وجود ندارد.

**راه‌حل پیشنهادی:**
سیستم ارزیابی مهارت با مقیاس ۱ تا ۱۰:

```typescript
// src/types/coach.ts
export type SkillCategory = 
  | 'passing' 
  | 'shooting' 
  | 'dribbling' 
  | 'defending' 
  | 'positioning' 
  | 'fitness' 
  | 'teamwork'

export interface SkillAssessment {
  id: number
  student_user_id: number
  coach_id: number
  skill: SkillCategory
  score: number          // 1-10
  assessment_date: string
  notes?: string
}

export interface ProgressReport {
  student_user_id: number
  assessments: SkillAssessment[]
  avg_score_change: number  // تغییر میانگین نسبت به ماه قبل
  strengths: SkillCategory[]
  weaknesses: SkillCategory[]
  recommendations: string[]
}
```

رابط کاربری:
- نمودار راداری (Radar Chart) برای نمایش پروفایل مهارتی شاگرد
- نمودار خطی برای نمایش روند پیشرفت در طول زمان
- قابلیت تولید گزارش PDF با لوگوی باشگاه

## نقاط درد فعلی (Pain Points)

### نقطه درد ۱: هماهنگی دستی زمان تمرین با شاگردان

**شرح مشکل:**
مربی باید در واتساپ یا تلگرام نظرسنجی ایجاد کند تا بهترین زمان تمرین را پیدا کند، سپس به صورت دستی زمین رزرو کند و دوباره در گروه اطلاع دهد. اگر یکی از شاگردان کنسل کند، باید جایگزین پیدا کند.

**آمار تقریبی:**
هر مربی هفته‌ای ۲-۳ ساعت فقط صرف هماهنگی زمانی می‌کند.

**راه‌حل پیشنهادی:**
سیستم نظرسنجی زمان داخلی:
- مربی ۳-۵ گزینه زمانی پیشنهاد می‌دهد
- شاگردان رأی می‌دهند
- سیستم به طور خودکار گزینه برتر را رزرو می‌کند
- اعلان خودکار به همه ارسال می‌شود

### نقطه درد ۲: پیگیری پرداخت‌های عقب‌افتاده

**شرح مشکل:**
مربی نمی‌داند کدام شاگردان شهریه ماه جاری را پرداخت نکرده‌اند مگر اینکه به صورت دستی چک کند. ارسال یادآوری نیز دستی است.

**راه‌حل پیشنهادی:**
داشبورد مالی مربی با هشدارهای خودکار:
- لیست شاگردان بدهکار با مبلغ و تاریخ سررسید
- دکمه «ارسال یادآوری» که پیامک/پوش نوتیفیکیشن ارسال می‌کند
- قفل خودکار رزرو آینده برای شاگردانی که بیش از ۲ ماه بدهکارند

### نقطه درد ۳: گزارش‌دهی به والدین

**شرح مشکل:**
والدین مرتباً از مربی می‌پرسند: «فرزندم چطور پیشرفت کرده؟» مربی باید به صورت دستی یادداشت‌های خود را مرور کند و پاسخ دهد.

**راه‌حل پیشنهادی:**
گزارش خودکار ماهانه:
- سیستم به طور خودکار در پایان هر ماه، گزارش پیشرفت را تولید می‌کند
- شامل: درصد حضور، نمرات مهارتی، نقاط قوت/ضعف، توصیه‌ها
- ارسال خودکار به ایمیل/پیامک والدین

## سناریوهای کاربردی نمونه

### سناریو ۱: مربی تیم نوجوانان

**زمینه:**
مربی علی، مسئول تیم ۱۵ نفره نوجوانان باشگاه استقلال است. او هفته‌ای ۳ جلسه تمرین دارد و شهریه ماهانه ۲ میلیون تومان از هر شاگرد دریافت می‌کند.

**جریان کاری ایده‌آل:**
1. **ابتدای ماه:**
   - سیستم به طور خودکار فاکتور شهریه برای ۱۵ شاگرد ایجاد می‌کند
   - پیامک یادآوری ارسال می‌شود
   - تا پایان هفته، ۱۲ نفر پرداخت می‌کنند، ۳ نفر عقب می‌افتند

2. **هر جلسه تمرین:**
   - مربی وارد اپلیکیشن می‌شود، لیست شاگردان را می‌بیند
   - با تیک زدن، حضور ۱۳ نفر را ثبت می‌کند (۲ نفر غایب)
   - سیستم به طور خودکار به والدین غایبین پیامک می‌زند

3. **پایان ماه:**
   - مربی ارزیابی مهارتی شاگردان را ثبت می‌کند
   - سیستم گزارش PDF تولید و به والدین ارسال می‌کند
   - داشبورد مالی نشان می‌دهد ۳ نفر هنوز بدهکارند (جمعاً ۶ میلیون)
   - مربی دکمه «ارسال اخطار نهایی» را می‌زند

**زمان صرفه‌جویی شده:**
- هماهنگی زمانی: ۲ ساعت/هفته → ۱۵ دقیقه/هفته
- پیگیری پرداخت: ۱ ساعت/هفته → ۱۰ دقیقه/هفته
- گزارش‌دهی: ۳ ساعت/ماه → ۰ دقیقه (خودکار)

### سناریو ۲: مربی خصوصی با چندین شاگرد

**زمینه:**
مربی مریم، ۸ شاگرد خصوصی دارد که هر کدام برنامه تمرینی متفاوتی دارند. برخی هفته‌ای ۱ جلسه، برخی ۳ جلسه.

**چالش خاص:**
- هر شاگرد سطح مهارتی متفاوتی دارد
- برخی شاگردان تخفیف ویژه دارند (مثلاً خواهر و برادر)
- نیاز به فاکتور رسمی برای برخی شرکت‌ها

**راه‌حل:**
- پروفایل مهارتی جداگانه برای هر شاگرد
- سیستم تخفیف انعطاف‌پذیر (درصدی یا مبلغ ثابت)
- تولید فاکتور PDF با شماره سریال و QR Code

## نتیجه‌گیری

نقش مربی در حال حاضر در سیستم رزرو فوتسال نادیده گرفته شده است. مربیان مجبورند از ترکیبی از ابزارهای دستی (واتساپ، اکسل، دفترچه) استفاده کنند که ناکارآمد و خطاپذیر است. با پیاده‌سازی ماژول‌های اختصاصی برای مدیریت برنامه تمرینی، حضور و غیاب، شهریه و ارزیابی پیشرفت، نه تنها بهره‌وری مربیان افزایش می‌یابد، بلکه تجربه شاگردان و والدین نیز به طور چشمگیری بهبود می‌یابد. این سرمایه‌گذاری مستقیماً به حفظ شاگرد (Retention Rate) و رشد درآمد باشگاه منجر می‌شود.
